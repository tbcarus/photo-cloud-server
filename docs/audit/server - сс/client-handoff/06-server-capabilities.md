# 06. Server Capabilities

> Что сервер умеет и не умеет — по состоянию кода на 2026-09-10 (HEAD `c2e9593`).
> Колонка **Supported**: ✅ полностью · ⚠️ частично / с ограничениями · ❌ нет.

---

## 1. Аутентификация и аккаунт

| Capability | Supported | Endpoint / mechanism | Notes |
| --- | --- | --- | --- |
| Регистрация | ✅ | `POST /api/v1/auth/register` | `201`; аккаунт создаётся **disabled** |
| Подтверждение email | ✅ | `GET /api/v1/auth/register/confirm?code=` | ответ **`text/plain`**; код живёт 3 дня |
| Повторная отправка письма активации | ❌ | `POST /auth/register/resend` → **`501`** | ⚠️ потеря письма = тупик: повторная регистрация даёт `409` |
| Login | ✅ | `POST /api/v1/auth/login` | возвращает access + refresh |
| Обновление access token | ✅ | `POST /api/v1/auth/refresh-token` | публичный; возвращает **только** access |
| Ротация refresh token | ❌ | — | refresh не меняется весь срок (7 дней) |
| Logout (текущая сессия) | ✅ | `POST /api/v1/auth/logout` | **требует валидный access token** |
| Logout на всех устройствах | ✅ | `POST /api/v1/auth/logout-all` | |
| Logout на всех, кроме текущего | ✅ | `POST /api/v1/auth/logout-others` | |
| Отзыв access token | ❌ | — | не хранится; живёт до 20 минут после logout |
| Запрос сброса пароля | ✅ | `POST /auth/password/reset/request?email=` | email в **query** |
| Подтверждение сброса пароля | ✅ | `POST /auth/password/reset/confirm` | ⚠️ **не отзывает refresh-токены** |
| Веб-страница сброса пароля | ❌ | `GET/POST /auth/password/reset/page` → **`501`** | ⚠️ **письмо ведёт именно сюда** — flow не работает через браузер |
| Повторная отправка ссылки сброса | ❌ | `POST /auth/password/reset/resend` → `501` | |
| Смена пароля со старым паролем | ❌ | — | только через email-код |
| Смена email | ❌ | — | email = логин, менять нельзя |
| Удаление аккаунта | ❌ | — | endpoint отсутствует |

| Multi-device | ⚠️ | косвенно через несколько refresh-токенов | сервер **не различает** устройства; модели `Device` нет |
| Ограничение числа сессий | ❌ | — | каждый login создаёт новую |
| MFA / 2FA | ❌ | — | |
| OAuth / внешние провайдеры | ❌ | — | |
| Rate limiting | ❌ | — | клиент должен ограничивать себя сам |
| Роли и права | ⚠️ | роли выдаются и попадают в JWT | **сервер их нигде не проверяет** |
| Блокировка (ban) | ⚠️ | флаг `banned` учитывается при login | механизма установки нет; на выданные токены не влияет |

## 8. Сводка для планирования клиента

**Что клиент может полностью полагать на сервер:**

- аутентификация с автообновлением access token;
- дерево папок с гарантией уникальности имён;
- дедупликация в пределах папки (можно грузить не глядя — дубль не создастся);
- корректные `checksum`, `size`, `mimeType`, `fileType` (сервер считает сам, клиенту доверять не нужно);
- EXIF-метаданные изображений.

**Что клиент обязан делать сам:**

| Задача | Почему |
| --- | --- |
| Хранить состояние синхронизации | сервер его не знает |
| Считать SHA-256 локальных файлов | для pre-check |
| Строить и поддерживать локальный индекс `checksum → serverId` | нет delta-sync |
| Генерировать миниатюры | сервер их не отдаёт |
| Обрабатывать EXIF Orientation | не извлекается сервером |
| Извлекать длительность видео | сервер её не знает |
| Ограничивать частоту запросов | rate limiting отсутствует |
| Управлять очередью и ретраями загрузки | ретраев на сервере нет |
| Обрабатывать прерванные загрузки повторной попыткой с нуля | resumable upload нет |
| Опрашивать сервер для обнаружения изменений | push нет |
| Переименовывать при `409` | auto-rename нет |
| Удалять пустые папки перед удалением родителя | рекурсивного удаления нет |
| Предупреждать о невозможности повторно получить письмо активации | resend = `501` |

**Функции, которые нельзя показывать в UI (сервер не поддерживает):**

корзина и восстановление, альбомы, теги, поиск, расшаривание, публичные ссылки, редактирование профиля и настроек, смена пароля из приложения, удаление аккаунта, список устройств/сессий, серверные миниатюры, докачка загрузок и скачиваний.
