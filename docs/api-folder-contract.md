# Folder API contract

Документ описывает текущий контракт папок. Базовый путь: `/api/v1/folders`. Все endpoint-ы требуют `Authorization: Bearer <accessToken>`.

## Модель

`Folder` хранит логическую структуру пользователя в БД:

| Field | Описание |
| --- | --- |
| `id` | id папки |
| `user` | владелец |
| `parent` | родительская папка, `null` только у ROOT |
| `name` | имя до 255 байт UTF-8 |
| `folderType` | `ROOT`, `CAMERA`, `USER` |
| `createdAt` | дата создания |
| `updatedAt` | дата обновления |

Response DTO:

```json
{
  "id": 10,
  "parentId": 1,
  "name": "Trips",
  "folderType": "USER",
  "createdAt": "2026-05-17T10:15:30",
  "updatedAt": "2026-05-17T10:15:30"
}
```

`children` не хранятся отдельной коллекцией в entity-контракте. Дочерние папки запрашиваются через repository по `userId + parentId`.

## Типы папок

| Type | Назначение |
| --- | --- |
| `ROOT` | корневая папка пользователя |
| `CAMERA` | системная дочерняя папка ROOT для `IMAGE` и `VIDEO` при upload без `folderId` |
| `USER` | пользовательские папки |

## Инварианты

- У пользователя ровно один `ROOT`; он создается лениво при первом обращении.
- `CAMERA` создается лениво как дочерняя папка `ROOT`: запросом `POST /api/v1/folders/camera` либо upload медиа без `folderId`.
- `USER`-папки могут быть вложенными в `ROOT` или другие `USER`-папки.
- `ROOT` и `CAMERA` нельзя переименовывать, перемещать или удалять.
- Внутри `CAMERA` нельзя создавать или перемещать папки.
- Имя `Camera` зарезервировано внутри `ROOT` без учета регистра, в том числе пока системная папка не создана.
- Файлы и папки одного parent используют одно пространство имён без учета регистра: занятое имя даёт `409`.
- Правила имени — в `api-file-contract.md`, раздел «Правила имен»; некорректное имя даёт `400` и не исправляется автоматически.
- Move проверяет, что папка не перемещается в саму себя или в своего потомка.
- Delete `USER`-папки удаляет всё её содержимое: записи поддерева удаляются сразу, байты — фоновой очисткой.


## Endpoints

### `GET /api/v1/folders/root`

Возвращает `ROOT` текущего пользователя. Если ROOT еще нет, создает его.

Response `200 OK`:

```json
{
  "id": 1,
  "parentId": null,
  "name": "root",
  "folderType": "ROOT",
  "createdAt": "2026-05-17T10:15:30",
  "updatedAt": "2026-05-17T10:15:30"
}
```

### `POST /api/v1/folders/camera`

Возвращает `CAMERA` текущего пользователя. Если её или `ROOT` еще нет, создает их. Запрос идемпотентен: повторные и параллельные запросы получают одну папку. Тело запроса не требуется. Выполняется под блокировкой строки `ROOT` пользователя.

Android вызывает его до pre-check и upload и передаёт полученный `id` как `folderId`.

Response `200 OK`: `FolderDto` с `folderType = CAMERA`, `name = Camera`, `parentId` равным `ROOT`.

### `GET /api/v1/folders/{id}/children`

Возвращает только прямых потомков папки. Рекурсивное дерево не возвращается.

Response `200 OK`:

```json
[
  {
    "id": 2,
    "parentId": 1,
    "name": "Camera",
    "folderType": "CAMERA",
    "createdAt": "2026-05-17T10:15:30",
    "updatedAt": "2026-05-17T10:15:30"
  }
]
```

Если папка не найдена или принадлежит другому пользователю: `404`.

### `POST /api/v1/folders`

Создает `USER`-папку. Если `parentId=null`, parent будет текущий `ROOT`.

Request:

```json
{
  "parentId": 1,
  "name": "Documents"
}
```

Validation:

| Field | Правила |
| --- | --- |
| `parentId` | optional |
| `name` | not blank, max 255 символов; дополнительно правила имени в service, значение не изменяется |

Response `200 OK`: `FolderDto` созданной папки.

Ошибки:

| Status | Когда |
| --- | --- |
| 400 | blank name, некорректное имя, попытка создать папку внутри `CAMERA` |
| 404 | parent не найден или не принадлежит пользователю |
| 409 | имя занято файлом или папкой в parent либо зарезервировано в ROOT |

### `PATCH /api/v1/folders/{id}`

Переименовывает только `USER`-папку.

Request:

```json
{
  "name": "Archive"
}
```

Response `200 OK`: обновленный `FolderDto`.

Ошибки:

| Status | Когда |
| --- | --- |
| 400 | попытка переименовать системную папку, blank/некорректное имя |
| 404 | папка не найдена или чужая |
| 409 | имя занято файлом или папкой в parent либо зарезервировано в ROOT; смена только регистра собственного имени конфликтом не считается |

### `POST /api/v1/folders/{id}/move`

Перемещает только `USER`-папку в `ROOT` или другую `USER`-папку.

Request:

```json
{
  "targetParentId": 12
}
```

Response `200 OK`: обновленный `FolderDto`.

Ошибки:

| Status | Когда |
| --- | --- |
| 400 | move системной папки, target равен самой папке, target находится внутри переносимой папки, target=`CAMERA` |
| 404 | папка или target parent не найдены или чужие |
| 409 | имя папки занято файлом или папкой в target parent либо зарезервировано в ROOT |

### `DELETE /api/v1/folders/{id}`

Удаляет `USER`-папку со всем содержимым. В одной транзакции под блокировкой `ROOT` удаляются записи поддерева и верхний каталог переносится в `.pending-delete/folder-{id}`; имя свободно сразу после ответа. Физическое содержимое удаляет фоновая очистка.

Response `204 No Content`.

Ошибки:

| Status | Когда |
| --- | --- |
| 400 | попытка удалить системную папку |
| 404 | папка не найдена или чужая |

## Physical tree

Папке `USER` соответствует каталог `{storage.root}/{userId}/files/...` с тем же именем; `ROOT` соответствует `{userId}/files`. Create, rename и move выполняют физическое действие в транзакции под блокировкой `ROOT`. Имя, занятое на диске без записи в БД, и файл, открытый внутри каталога на Windows, дают `409` без изменений.

## Security

Все операции используют текущего `@AuthenticationPrincipal User`. Доступ к чужой папке не раскрывается отдельным `403`; repository lookup идет по `id + userId`, поэтому клиент получает `404`.
